# P01 后续动作

P01 已收口。以下仅是 P02 的进入条件和准备清单，不代表 P02 已获批准或已开始。

1. 等待用户明确批准 Phase P02；批准前不得创建数据接入、Provider Worker、资产扫描
   或新的数据库业务表。
2. P02 启动时先读取任务书、当前状态、P01 八件套和所有开放风险，建立新的需求追踪
   切片与实施计划。
3. 在不读取内容的前提下设计本地资产授权流程；任何路径访问仍需用户按最小范围明确
   授权。
4. 为 Provider Registry、point-in-time 数据、许可标签、内容修订/删除和可重放 ingest
   建立正式契约。
5. 为 P02 数据 parser 设坏输入、契约、覆盖和性能门，禁止用实时外部 API 作为 CI
   依赖。
6. 继续保持所有真实账户、交易所私有 API、Cookie、验证码和 API Secret 禁止访问；
   `LIVE_TRADING` 必须保持锁定。
7. 评估 P01 开放风险是否影响 P02；若 PostgreSQL 来源、Node 基线或 Nautilus 契约变化，
   先新增 ADR 和兼容测试，不得静默换版本。

在新批准到来之前，当前可执行动作仅限 P01 证据维护和缺陷修复。
