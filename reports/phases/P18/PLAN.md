# P18 实施计划

## 目标与边界

汇总 P00–P17 的代码、测试、运行证据与未关闭风险，执行独立 Canary Go/No-Go 审查，并建立持续运营
制度。P18 本身不启用 Live；默认结论为 `NO_GO`，除非每个硬条件均有真实证据。即使未来得到 `GO`，
仍须保持 `LIVE_TRADING` 锁定，等待用户在独立流程中明确批准和单次人工解锁。

当前没有专用低余额子账户、无提现/IP 白名单 API、真实 Testnet、外部 SEV0/SEV1 到达性、目标
Linux/Docker、真实 IdP/CA、异机备份、付费 Provider 实测或 12h/24h 长稳证据。因此本阶段必须诚实
输出 `NO_GO`，不得借助 fixture、Paper 盈亏、界面或工程完成度冒充 Canary readiness。

## 实施顺序

1. 固化 14 项任务和 7 项验收条件的 P18 可追踪矩阵，并读取 P00–P17 状态、报告和开放风险。
2. 建立类型化 Readiness 证据、硬门、阻断原因、Canary 范围、资本阶梯、停止条件和运营周期契约。
3. 生成 P00–P17 聚合证据，区分已通过的工程门、延期验收、外部输入缺口和不可替代的真实运行证据。
4. 最多选择一个策略、一个账户范围和少量高流动性合约；证据不足时合法选择 0 个并明确原因。
5. 冻结候选代码、模型、策略、风险、执行、数据和依赖版本，生成不可发布的 Canary Release Manifest。
6. 对 Manifest 计算规范摘要，记录签名状态和到期时间；`NO_GO` 时禁止签发可执行 Live 授权。
7. 验证专用子账户、低余额、无提现、IP 白名单和最小权限；未提供时逐项 `BLOCKED_EXTERNAL_INPUT`。
8. 汇总 Paper/Shadow/Testnet、风险、kill switch、告警、值守、回放、对账、恢复、mutation 与 chaos 证据。
9. 定义零资本锁定层和未来未批准的双重硬上限资本阶梯，以及完整停止、退回和人工恢复规则。
10. 执行独立 Go/No-Go 评估；任一硬门不通过即 `NO_GO`，禁止使用加权平均抵消安全缺口。
11. 生成任务书规定的七份 live-readiness 报告和每日/每周/每月/季度运营制度。
12. 生成只在所有前置门关闭后才可行动的用户人工确认清单，不索取任何秘密值。
13. 接入 P18 CI、变异测试、严格类型、安全扫描、候选 Python 和全仓回归门禁。
14. 生成 P18 阶段报告和工件清单，保持 `ACCEPTANCE.md` 不存在并更新最终阶段状态。

## 明确非目标

- 不创建或连接真实交易账户、子账户、API、提现权限、IP 白名单或 Live endpoint。
- 不选择未经完整 OOS、Paper/Shadow/Testnet 和风险证据支持的策略作为可执行 Canary。
- 不签发 Live 解锁令牌，不实现自动解锁，不创建 `src/aegisquant/live`。
- 不把 P03 的 24h waiver、P13 的逻辑周期、fixture、Testnet 盈亏或自动化 CI 当作真实长稳证据。
- 不执行 12h/24h 验收，不生成 `ACCEPTANCE.md`，不把 `NO_GO` 视为工程失败。
