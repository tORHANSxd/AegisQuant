# P17 实施计划

## 目标与边界

在现有免费官方数据、公开事件与研究基线之上，建立可复现、可拒绝、默认不采购的付费 Provider
Bake-off。P17 只评估候选和生成最小试用申请包；没有用户批准的预算、试用权限和本地秘密引用时，
所有需认证候选保持 `NOT_TESTED`/`candidate`，不得进入 Provider Registry `approved`，不得成为运行时
硬依赖。

P17 不连接真实账户，不执行交易，不向第三方上传项目数据，不索取或写入密码、Cookie、验证码或
API Secret。官方交易所数据继续是交易事实权威；任何聚合源只能提供研究增量，不能替代官方事实。
正式验收按 ADR-0010 延后，不执行 12h/24h 验收。

## 实施顺序

1. 固化 15 项任务与 5 项验收条件的阶段可追踪矩阵，并定义采购、拒绝、延后与证据不足状态。
2. 建立严格的 Provider 候选、试用计划、预算、许可、运行成本、质量、新闻价值与降级契约。
3. 为 Tardis/Kaiko、CoinGlass、CryptoQuant/Glassnode、条件式 Databento、两档新闻源和 X API 建立
   候选登记与同类互斥规则。
4. 从官方稳定文档核验数据范围、访问方式、历史覆盖、用量/价格披露状态和许可入口；营销材料不能
   作为购买证据，无法确认的数据明确标记未知。
5. 生成每类最小试用数据需求、假设、调用量、存储量、最长试用时长、成本上限、成功/失败标准与
   硬停止条件；未获批准时不发起认证请求。
6. 实现可复现的同预算 `Baseline` vs `Baseline+Source` 消融评测，使用确定性公开/合成 fixture 验证
   评分逻辑，不把 fixture 结果冒充任何商业 Provider 实测。
7. 对新闻类实现 recall、false alert、lead time、转载重复率、风险覆盖价值和官方事实交叉核验指标。
8. 对市场/链上类实现历史覆盖、缺口、修订/删除、首发延迟、许可、价格、运维、OOS 净增量评分。
9. 实现 feature importance 之外的净交易增量判定，并扣除数据、存储、运维、交易成本和多重比较影响。
10. 实现 Provider 停服降级演练，证明候选未购买时不是硬依赖，停服时退回免费基线且保持安全状态。
11. 对 HKUDS/AI-Trader 只做许可证、架构和思想映射复核，不执行第三方脚本、不复制未知许可代码、
    不采用其收益声明作为采购或策略证据。
12. 输出完整负结果和 `NO_PURCHASE`/`DEFER` 建议；同类首期长期主源上限为 1，证据不足时为 0。
13. 扩展 P17 CI、属性测试、变异测试、安全扫描、兼容性和全量回归门禁。
14. 生成 P17 强制报告、工件清单和 ADR 引用，保持 `ACCEPTANCE.md` 不存在。
15. 更新阶段状态，提交实现与证据并按项目配置执行一次本地 Git 归档。

## 明确非目标

- 不购买、开通或续费任何 Provider，不创建试用账号，不绕过登录、地域、条款或配额限制。
- 不接收或保存第三方 API Secret；只允许未来由用户在本地秘密库配置引用名称。
- 不批准任何未完成真实试用、OOS 消融、许可与运维审查的 Provider。
- 不把营销历史覆盖、样例响应、合成 fixture 或文档评审称为真实 Provider 数据表现。
- 不把第三方聚合作为订单、成交、余额、仓位、保证金或交易规则的权威来源。
- 不开始 P18，直到 P17 实现与证据提交完成。
