# P11 实施计划

## 目标与边界

P11 在 P05 的复式账本、P06 的成本/成交/保证金/压力回放、P07 的严格验证、P08 的 Proposal-only
AI 边界和 P10 的事件风险证据之上，建立组合构建与独立风险引擎。唯一允许的业务链路为：信号先
转换为受成本、容量和组合约束的 `PortfolioProposal`，再由独立 `RiskSnapshot` 与签名版本化政策
生成 `RiskDecision`；只有未过期且批准的决策才能产生 Paper `OrderIntent`。研究、模型和 LLM 不得
导入、调用或拥有 Risk override，也不存在自动放宽风险的接口。

本阶段继续保持 `LIVE_TRADING=false`、`live_trading_locked=true` 和空 Live adapter registry。不连接
真实交易账户，不访问账户秘密，不创建真实 `OrderCommand`。任务书中的示例数值全部标记为
`EXAMPLE_ONLY`，用户尚未确认更高部署阶段时仅允许 `PAPER`。正式验收按 ADR-0010 统一后置：P11
完成实现和测试后仍保持 `in_progress`，不生成 `ACCEPTANCE.md`，不写 `accepted_at_utc`。

## 实施顺序

1. 建立 P11 需求可追踪矩阵，并以 ADR 固化组合投影、风险独立性、自动状态单向安全迁移、签名
   政策、传闻处置和 Paper-only 边界。
2. 实现严格的信号输入、置信度折扣、截断归一化和 no-trade zone；低置信度或不足以覆盖交易摩擦
   的变化保持当前权重。
3. 实现对角 shrinkage 协方差、因子贡献和市场状态乘数；缺失、非对称、负方差、未来可用或陈旧
   风险估计失败关闭。
4. 实现保守的 robust portfolio projection：风险预算、vol target、不确定性折扣、总杠杆和资产/
   合约/策略/袖套/交易所/稳定币/相关簇约束均只能缩小候选，不得放大信号。
5. 实现 turnover、冲击和 ADV 容量约束，输出每腿信号、预期收益、风险、成本、容量和约束贡献；
   所有 Decimal 经济值保留显式单位和确定性计算。
6. 实现独立 `RiskSnapshot`、版本化 `RiskPolicy`、内容哈希和 Ed25519 公钥验签；仓库与报告只保存
   公钥、签名和哈希，不保存私钥或其他秘密。
7. 实现订单、资产、策略和账户级预交易门禁。期望订单方向或规模不得超过已批准组合变化；
   `REDUCE_ONLY` 只能减少绝对风险，`HALTED` 禁止创建订单意图。
8. 实现 `NORMAL → CAUTION → REDUCE_ONLY → HALTED` 的自动单向安全迁移；`RECOVERY` 与恢复到较低
   风险状态必须由非 AI 人工授权并满足数据、模型、账本、保证金、流动性、交易所、安全和事件
   前置条件。
9. 实现数据、模型、损失、保证金、流动性、交易所、安全和重大事件熔断器，以及风险事件、告警、
   原因码和恢复前置条件。
10. 实现经过签名的官方安全事故、暂停提现、稳定币脱锚、重大监管和基础设施事件剧本；传闻只
    允许监控、收紧限额或有上限减仓，不能由 LLM 决定全平。
11. 实现 Kill Switch、Reduce-only 和恢复序列的确定性风险回放，并实现价格、相关性、流动性、
    保证金、交易所和稳定币压力场景。
12. 使用 Hypothesis 随机测试证明全部约束成立、策略无法放大批准目标、自动状态不能变得更冒险；
    使用定向 mutation 测试关键拒绝条件。
13. 生成 P11 机器证据、风险政策/签名、组合提案、风险决策、回放和压力报告；运行全量 pytest、
    Ruff、Pyright、Python 3.14、mutation、安全、依赖、许可证、前端构建与 E2E。
14. 生成延期验收口径的 SUMMARY、TEST_RESULTS、RISKS、NEXT_ACTIONS、ARTIFACT_MANIFEST 和
    ADR_REFERENCES，更新阶段状态并执行一次本地 Git 归档。

## 验证标准

- 每个 `OrderIntent.risk_decision_id` 可回溯到同一 `PortfolioProposal`、独立快照、签名政策版本和
  未过期批准；缺少任一环节均失败关闭。
- 研究/模型包不得依赖风险实现，代码库中不存在 override/bypass API；AI 只产生 Proposal。
- 风险快照或模型输入陈旧时拒绝新增风险，不能用旧缓存隐式放行。
- 自动转换的目标状态安全等级不得低于当前状态；恢复必须人工授权且前置条件全部满足。
- 随机组合输入下，总敞口、分组约束、换手、冲击、容量、vol target 和预交易限制均成立。
- Kill Switch 和 Reduce-only 的事件、决策、状态与恢复过程可以按原顺序重放并获得相同结果。
- 示例风险数值只在 Paper 环境生效，不会成为 Live 默认值；P11 不产生真实命令或外部副作用。

## 明确非目标

- 不做真实账户接入、Testnet/Live 下单、交易所账户流或订单状态机；这些属于 P12 及之后阶段。
- 不提供风险 override、紧急放宽、AI 审批、传闻全平或自动恢复捷径。
- 不把确定性夹具、压力场景或示例参数解释为实盘风险校准、Alpha 或收益保证。
- 不以优化器数值收敛为理由绕过硬约束；任何数值异常、陈旧或缺失输入均拒绝新增风险。
- 不做正式 P11 验收，不解除最终 Holdout 或 Live 锁，不在证据提交前开始 P12。
