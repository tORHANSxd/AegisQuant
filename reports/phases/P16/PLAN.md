# P16 实施计划

## 目标与边界

把 P00-P15 已验证的研究、Paper、Shadow、Testnet 契约和只读工作台变成可观测、可告警、可恢复、
可安全部署的运行系统。P16 不连接真实账户，不启用 Live，不收集任何明文密码、Cookie、验证码或
API Secret；生产配置只接受秘密引用，研究服务不挂载交易秘密。

正式验收按 ADR-0010 延后。本阶段执行确定性契约、安全、故障、真实临时 PostgreSQL 备份恢复和
静态部署配置验证，但不伪造本机缺失 Docker 所需的容器运行证据，也不执行 12h/24h 验收。

## 实施顺序

1. 固化 12 项任务与 7 项验收条件的阶段可追踪矩阵，并记录官方稳定版本与主机能力差异。
2. 实现低基数 Prometheus 指标、结构化脱敏 JSON 日志、OpenTelemetry trace/span 关联与非阻塞导出。
3. 为只读 API 接入相关 ID、安全响应头、指标端点和可选离线 OIDC JWT 验证，保持 localhost 默认值。
4. 实现 SEV0-3 告警、路由、去抖、抑制、维护窗口、事故生命周期和本地 webhook 契约。
5. 建立 Prometheus、Grafana、Loki、Alloy、Alertmanager、Tempo 的生产 Compose 配置和六类仪表板。
6. 建立 systemd 服务、反向代理、网络隔离、秘密挂载、时间同步、磁盘与资源预警。
7. 实现加密、校验、留存受控的 PostgreSQL 备份包，并在一次性 PostgreSQL 上恢复后验证账本与对账。
8. 实现 Ed25519 发布清单签名、审批门和失败安全回滚；错误版本只能保持 HALTED/REDUCE_ONLY。
9. 补齐第 18 章十二份规范 Runbook、事故模板、威胁模型与 Paper/Testnet 部署手册。
10. 扩展 SBOM、SAST、依赖、许可证、秘密、容器/IaC 静态扫描和 P16 CI。
11. 执行安全、故障、备份恢复、发布回滚、变异和全量回归测试，生成阶段强制证据。
12. 更新阶段状态，提交实现与证据并按项目配置执行一次本地 Git 归档。

## 明确非目标

- 不启用或提供 `LIVE_TRADING` 解锁路径，不连接真实交易账户或真实下单网络。
- 不把 Grafana 当作主业务看板，不开放公网管理端口，不使用 Promtail、Kafka 或 Kubernetes。
- 不宣称 SEV0/SEV1 已到达用户外部渠道；未配置渠道时只验证 loopback 接收契约并保留验收缺口。
- 不因本机无 Docker 而伪造容器启动、镜像漏洞运行扫描或生产部署通过记录。
- 不开始 P17，直到 P16 实现与证据提交完成。
