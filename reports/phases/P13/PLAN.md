# P13 实施计划

## 目标与边界

P13 在 P11 的独立风险决策和 P12 的幂等执行、账户对账、原子账本之上，建立不使用真实资金的
实时 Paper、严格只读 Shadow、历史回放和 Chaos 验证运行层。同一风险批准的策略决策必须在
`HISTORICAL_REPLAY`、`PAPER`、`SHADOW` 三种模式中保留相同的预测、目标、方向、数量、
`risk_decision_id`、经济幂等键和命令身份；允许不同的只有市场可用时间、可成交价格、虚拟成交和
观测到的拒绝/限频事实。

`SHADOW` 只能消费公共行情和可选只读账户快照，只记录“本来会下什么单”，类型和模块边界均不
提供 submit/cancel/amend 或交易凭据能力。`PAPER` 使用实时语义的虚拟成交模型并写入项目自有
模拟账本，不向交易所发请求。继续保持 `LIVE_TRADING=false`、`live_trading_locked=true`，不读取
秘密、不连接真实交易账户、不启用 Testnet/Live 发送。

用户已经决定开发期间不运行 12h/24h 正式验收并把验收统一后置。P13 将运行七个逻辑日的加速
稳定性、内存有界、重启和故障契约，但明确标记 `qualifying_wall_clock_acceptance=false`；它不能
替代真实长时墙钟运行。ADR-0018 定义若未来恢复该项时的 12 小时最低资格和禁止伪造规则。

## 实施顺序

1. 建立 P13 需求追踪矩阵，并以 ADR 固化三模式同语义、Shadow 无写能力、故障降级、事件/告警、
   检查点恢复和长期测试延期口径。
2. 建立带事件时点、可用时点、来源哈希、盘口和序列的统一 `MarketObservation`，以及预测、目标、
   风险决策、命令和成交的端到端 trace contract。
3. 实现实时 Paper 成交模型，覆盖延迟、bid/ask、限价保护、部分成交、参与率、滑点、费用、重复
   行情事件和经济幂等。
4. 实现 Paper checkpoint/restore；恢复时重建订单、Fill、经济幂等和已处理事件集合，禁止重启后
   重复订单、重复 Fill 或重复账本事实。
5. 实现 Shadow 只读运行器，只接受公共行情与显式 `write_permissions=false` 的账户观察；输出
   hypothetical order 和当时可成交价格，不依赖或暴露 `ExecutionAdapter`。
6. 实现历史回放、Paper、Shadow 的统一 runner 和语义比较，证明同一策略/风险输入的目标、命令和
   身份一致，同时保留各模式成交差异。
7. 实现预测→目标→订单→可成交价格→虚拟成交价格的数量、延迟、spread、slippage、fee 和未成交
   原因分析。
8. 实现运行守护、心跳、检查点、重启预算、固定容量健康历史和安全状态迁移；数据/模型陈旧、网络、
   数据库、时钟或进程故障不得继续新增风险。
9. 实现每日 Paper 订单/Fill/账本/Read Model 输入对账；差异生成阻断性案例，不能自动改写权威事实。
10. 实现网络、数据库、模型、数据源、时钟和进程六类 Chaos 演练，以及 SEV0/SEV1 时间线、恢复
    证据、告警与 Runbook 绑定。
11. 建立 P13 所需 Runbook，逐份包含检测、立即动作、禁止动作、证据收集、恢复条件和演练记录。
12. 运行历史重大事件形态回放，使用明确标记的归一化公开历史情景；不把近似夹具冒充逐笔原始数据。
13. 生成候选策略 Paper/Shadow Scorecard，保留负结果、成交误差、降级、恢复、对账和容量差异。
14. 使用单元、属性、契约、集成、历史回放、Chaos 和定向 mutation 测试覆盖幂等、单调、只读、
    有界内存和故障恢复。
15. 运行全量 pytest、Ruff、Pyright、Python 3.14、mutation、Bandit、秘密、依赖、许可证和前端
    流水线。
16. 生成延期验收口径的 SUMMARY、TEST_RESULTS、RISKS、NEXT_ACTIONS、ARTIFACT_MANIFEST 和
    ADR_REFERENCES，更新状态并执行一次本地 Git 归档；随后自动进入下一阶段。

## 验证标准

- 同一决策在历史回放、Paper、Shadow 中的预测、目标、方向、数量、风险决策和经济幂等身份一致。
- Paper 只能产生虚拟订单/Fill；重复市场事件、重放和重启均不重复经济订单、Fill 或账本事实。
- Shadow 源码和运行对象没有交易写方法、交易 Adapter、Live 域名、凭据读取或账户写权限。
- 数据或模型陈旧、数据库不可用、时钟漂移、网络断开和进程崩溃触发既定降级/Halt 与告警。
- 订单、Fill、账本投影和 Read Model 输入每日对账一致；任何差异阻断新风险并保留证据。
- 六类 Chaos 场景均有确定性时间线、Runbook、恢复条件和零未知资金事实证明。
- 加速稳定性测试状态、逻辑时长、墙钟时长和资格标志分开记录，不冒充 12h/24h 验收。

## 明确非目标

- 不运行开发阶段的 12h/24h 墙钟验收，不把快速测试写成长期稳定性通过。
- 不发送 Testnet 或 Live 订单，不接入真实账户写权限，不请求任何明文凭据。
- 不把 Paper/Shadow PnL、成交率或历史情景结果解释为 Alpha、收益保证或实盘容量。
- 不在 P13 实现 P14 的 FastAPI、Read Model 查询服务或完整看板。
- 不做正式 P13 验收，不生成 `ACCEPTANCE.md`，不解除最终 Holdout 或 Live 锁。
