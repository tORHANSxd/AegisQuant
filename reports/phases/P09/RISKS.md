# P09 风险

## 已控制

- `P09-R01` 外部 Python、Notebook 或 HTML 产生副作用：所有来源先隔离，Python/Notebook 只读
  字节并解析 AST，HTML 只生成惰性文本；P09 不暴露来源代码执行 API。
- `P09-R02` ZIP 路径穿越、符号链接、压缩炸弹、宏或覆盖已有归档：严格路径、类型与资源上限，
  内容寻址发布且不可覆盖；Windows 瞬时目录锁仅做 3 次有界重试并有回归测试。
- `P09-R03` 权利未知内容进入公开工件：只有明确 `public_license` 且有许可证标识的内容允许公开
  正文；JoinQuant 队列和 AI-Trader 均保持 `unknown`、元数据-only。
- `P09-R04` AI 编造策略参数或证据：Proposal 的 claimed、IR referenced 与 available Evidence ID
  必须精确一致，缺失参数没有默认值，Proposal 没有执行或发布状态。
- `P09-R05` 未来函数、幸存者、成本或虚假成交污染研究：AST 与 Strategy Audit 显式标记并失败
  关闭；来源收益不被采用，迁移候选统一经过 P06 事件引擎重跑。
- `P09-R06` 同一策略换名后被当成多个 Alpha：七层指纹保留独立证据，复制改名簇只计一个 Alpha。

## 尚存且阻断对应正式验收项

- `P09-R07` 尚无用户合法提供的真实聚宽/米筐/BigQuant 导出，无法声称真实文章复现；状态保持
  `awaiting_user_export`，合成夹具只证明 importer 和静态分析契约。
- `P09-R08` AST 静态分析不是恶意代码证明，也不能完整推断动态语言、平台隐式成交或经济有效性；
  真实来源仍需人工审阅、PIT 重建和统一回测。
- `P09-R09` 三套迁移候选使用短小合成行情，只验证工程可复现性，不证明稳健性、Alpha 或未来盈利。
- `P09-R10` 外部框架和仓库的版本、许可证与文档会变化；未来采用前必须重新核对官方稳定契约，
  尤其不能把 GitHub 可见性当作许可。
- `P09-R11` 未实现可选浏览器扩展。当前 importer 已满足手工导出闭环；只有真实单页导出工作量
  明显成为瓶颈时，才值得增加扩展的权限与供应链攻击面。
- `P09-R12` 正式验收被项目业主统一后置。工程验证不等于阶段接受，更不允许解除 Live 锁。
