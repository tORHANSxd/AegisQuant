# P06 ADR 引用

| ADR | 对 P06 的约束 | 验证结果 |
|---|---|---|
| ADR-0001：运行时与版本政策 | Python 3.13 主运行时、3.14.7 候选契约和锁定依赖 | 两套运行时分别 277/240 passed；Node 版本警告登记为 P06-RISK-007 |
| ADR-0002：事件引擎选择 | 第三方引擎只能在实际契约满足时使用，领域事实不能外包 | Nautilus `1.231.0` 探针确定性通过；权威事实保留在 AegisQuant Decimal 与 P05 账本 |
| ADR-0003：Live Trading 锁 | 阶段不得拥有真实账户、认证或订单发送能力 | 状态、run manifest、安全扫描和证据均证明锁定且未访问账户 |
| ADR-0004：P01 领域契约与 PostgreSQL 技术栈 | 复用强类型 ID、Money、Fill、Journal 与精确数值不变量 | 回测订单/成交/账本 Schema 和双运行时测试通过 |
| ADR-0005：P02 列式数据底座与本地安全查询契约 | 输入事实必须保留时间、revision 与可重放边界 | run manifest 固定数据/配置/代码哈希、种子与复现命令 |
| ADR-0006：Binance 公开市场数据契约与安全边界 | 市场数据只能走公共无认证路径 | P06 只使用合成固定事件，未新增私有 API 或账户能力 |
| ADR-0007：P03 二十四小时连续流验收豁免 | 不执行、不拼接、不伪造 12/24 小时结果 | P06 仅执行秒级有界性能基准，CI 未调用 soak |
| ADR-0008：P04 多场所公共数据与事件来源契约 | 多场所输入可追溯且不能直接变成真实交易动作 | SIM/SIM2 非原子多腿仅在本地事件引擎执行并进入模拟账本 |
| ADR-0009：P05 权威会计、FIFO、估值与签名策略 | 所有模拟成交和现金流必须进入逐资产平衡的权威账本 | 部分成交、断线、多腿失败与强平闭仓均保持每笔分录平衡 |
| ADR-0010：延期统一验收下的阶段推进 | 实现验证与正式验收分离，不得伪造 accepted | P06 保持 `in_progress`，无 `ACCEPTANCE.md`、无 `accepted_at_utc`，未进入 P07 |
| ADR-0011：P06 双回测引擎、精度与模拟政策 | 固化双引擎职责、三档成交精度、历史成本、强平和性能政策 | 19 项追踪、Golden、property、replay、stress、benchmark 与 mutation 证据完成 |

NautilusTrader 官方稳定契约和实测结果存在字段语义差异：3 条 QuoteTick 输入对应
`iterations == 3`、`total_events == 0`。P06 按 ADR-0011 使用实际合同测试结果，没有凭字段名
猜测。HKUDS/AI-Trader 仅作为量化思路参考，本阶段未复制其浮点成本或平台耦合实现，也未新增
相关依赖。
