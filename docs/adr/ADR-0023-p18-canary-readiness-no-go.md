# ADR-0023：P18 Canary 硬门、零资本与非授权 Manifest

- 状态：Accepted
- 日期：2026-09-02
- 决策范围：P18

## 背景

P18 要求在考虑任何小额 Canary 前，汇总 P00–P17 的需求、风险、账本、执行、稳定性、安全、部署、
恢复和人工运营证据。当前没有经批准的策略候选、专用低余额账户、真实 Testnet 验收、外部关键告警
渠道、人工值守窗口、目标 Linux 运行证据或异机备份证据；用户同时明确延期正式验收且不执行
12h/24h 墙钟验收。因此，工程完工不能被表述为可实盘。

## 决策

1. Go/No-Go 只采用逐项硬门，不使用加权平均、收益抵消或多数通过。14 个门中任一 `FAILED` 或
   `BLOCKED_EXTERNAL_INPUT` 都强制 `NO_GO`。
2. 当前 Canary 范围显式为 `NONE_NO_GO`：不选策略、不选账户、不选合约。P08 的 `linear-fused` 仅是
   确定性开发样本上的观察候选，不构成 alpha、最终 Holdout 或 Live 批准。
3. 资本阶梯只有 `LOCKED` 层激活。未来 L1/L2 的硬代码资本天花板分别为 100/250 美元，但当前用户
   政策上限、有效资本、总名义、单笔名义、日损失和权益比例均为 0；有效资本始终取代码与用户政策
   两者较低值。
4. Canary Manifest 在 24 小时内到期，冻结实现提交、依赖版本和关键工件哈希。当前 Ed25519 密钥是
   可复现、未持久化、无信任锚的测试证据密钥，只验证签名实现和文件自洽；不证明发布者身份，不具备
   Live 授权能力，也不能用作人工批准或解锁令牌。
5. P18 不实现独立 Live 解锁流程。即使未来全部硬门通过并得到 readiness `GO`，`LIVE_TRADING` 仍须
   保持锁定，直至用户在另一个明确、单次、可审计的流程中批准并人工解锁。
6. 账户控制、真实 Testnet、外部告警/值守、目标 Linux、异机备份和墙钟验收缺证据时必须标为
   `BLOCKED_EXTERNAL_INPUT`，不得用 fixture、逻辑循环、本机模拟或营销文档冒充。
7. 所有停止条件自动进入“停止新风险、取消可确认订单、对账、人工恢复”姿态；任何未知订单状态、
   账本差异、数据失鲜、告警失联或权限漂移均不得自动恢复。
8. 按用户决定，本阶段不执行 12h/24h 验收、不生成 `ACCEPTANCE.md`。实现验证通过只记录为
   `implementation_verified_acceptance_deferred`。

## 后果

- P18 可以完整交付就绪评审、资本阶梯、停止条件、回退计划、人工清单和持续运营制度，同时诚实保持
  `NO_GO`、0 美元和 0 个真实订单。
- 当前 Manifest 的签名可用于契约与防误改测试，不能抵抗能够替换公钥和重签文件的攻击者；未来若要
  发布真实 Canary，必须另行配置受保护的发布密钥、独立审批信任锚和用户人工解锁。
- 正式验收、外部资源配置或 Live 授权均不因 P18 工程完成而自动获得；这些是后续独立决策，不存在
  “代码写完顺手开仓”这种离谱捷径。
