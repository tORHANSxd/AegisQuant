# ADR-0018：P13 Paper、Shadow、Chaos 与稳定性验证政策

- 状态：Accepted for implementation
- 日期：2026-09-02
- 决策范围：P13

## 背景

P13 需要让完整决策、风险、执行和账本语义在无真实资金时持续运行，并比较历史回放、Paper 与
Shadow。最大的工程风险不是“模拟能不能成交”，而是三种模式悄悄分叉、Shadow 获得写权限、超时
或重启生成重复经济事实，以及用几分钟测试冒充长期稳定性。

任务书要求至少一次由 Codex 定义持续期的长期稳定性测试。项目业主已明确决定开发阶段不执行
12h/24h 验收，并要求所有实现完成后统一验收。该决定不能被伪装成已通过，也不妨碍先实现守护、
检查点、内存有界和故障恢复契约。

## 决策

1. 唯一可比较的运行模式为 `HISTORICAL_REPLAY`、`PAPER`、`SHADOW`。三者消费同一风险批准的
   command bundle，预测、目标、方向、数量、风险决策、经济幂等和 client order identity 不得
   因模式改变。
2. Paper 订单和 Fill 是项目自有虚拟事实，只写模拟账本。成交模型显式使用可用时点、bid/ask、
   延迟、参与率、限价、滑点和费用；不能使用未来行情或把未成交强行填满。
3. Shadow 只允许公共行情和 `write_permissions=false` 的可选账户快照。Shadow 模块不得导入
   `ExecutionAdapter`，不得暴露 submit/cancel/amend，不得读取环境凭据，也不得实例化交易客户端。
4. 检查点包含订单、Fill、已处理市场事件和经济幂等集合的内容哈希。恢复必须验证哈希并重建全部
   去重索引；验证失败进入 `HALTED`，不能猜测或清空状态继续运行。
5. 数据陈旧、模型超时、网络断开进入 `DEGRADED` 并禁止新增风险；数据库不可用、无法验证检查点、
   超限时钟漂移或重启预算耗尽进入 `HALTED`。自动恢复只能回到 Paper/Shadow 原状态，不能升级环境。
6. 六类 Chaos 故障绑定显式告警、Runbook、时间线和恢复条件。演练环境为模拟，但 SEV 等级按若在
   交易关键路径发生时的生产影响分类；证据必须注明没有真实资金影响。
7. 当前运行七个逻辑日、10,080 个一分钟周期的加速稳定性测试，验证有界状态、检查点、恢复和
   决策确定性。报告必须同时记录逻辑时长与实际墙钟时长，并固定
   `qualifying_wall_clock_acceptance=false`。
8. 如果未来恢复墙钟稳定性验收，最低资格定义为连续 12 小时：进程未暂停、行情持续推进、至少一次
   计划内进程恢复、每小时内存斜率无持续正增长、无重复订单/Fill/账本、无未解释对账差异。实际
   墙钟不足 12 小时的结果在模型校验层禁止标记为 qualifying。
9. 用户当前决定优先级高于执行该长跑：P13 长期验收保持延期，不创建定时任务、不后台占用主机、
   不用加速结果替代。正式验收仍按 ADR-0010 后置。
10. Testnet 只验证 API 和恢复；其价格、流动性与 PnL 不能进入 Paper/Shadow Scorecard 的能力结论。

## 后果

- 好处：三模式共享经济身份，Shadow 在类型层无写能力，重启和故障不会生成重复资金事实；加速测试
  能在开发期快速抓住无界状态与恢复错误，同时不虚报长期运行。
- 代价：真实墙钟稳定性与公共行情长期可用性仍无证据，相关 acceptance 保持 `in_progress`；未来若
  业主恢复该项，需要独立运行并保存完整过程证据。
- 禁止：把逻辑时间写成墙钟时间、把 Testnet/Paper PnL 当作实盘证明、让 Shadow 共享交易 Adapter、
  在数据库或检查点未知时继续新增订单、因自动恢复改变到更高风险环境。
